## STAR 面试展开版

### S｜情境

科研资料可能来自不同学科，文档语言也不统一。中文问题检索英文论文时，BM25 缺少词面交集；PDF 双栏、公式、表格和页眉会进一步破坏正文顺序。原系统虽然经常能找到正确文档，但最初 document Recall@5 为 95.0%，精确段落 Recall@5 只有 50.0%，说明主要问题是“找到论文但找不到答案段落”。

### T｜任务

把系统改造成通用科研助手：支持中文提问和中英文资料；提高段落召回与首屏排序；没有证据时稳定拒答；所有答案必须有可核验引用；在本地应用、虚拟机数据库和云端 GPU 的现有环境中完成上线与回滚准备。

### A｜行动

1. 建立 50 题评测集，拆分 chunk/doc 的 Recall@1、Recall@5、Recall@10、MRR，以及拒答准确率、误拒率和引用逐字真实率。
2. 从召回漏斗定位问题，发现根因集中在 PDF 解析、跨语言检索、候选过早截断和 Agent 重试覆盖证据，而不是单纯的 Milvus 参数。
3. 重写 PDF 版面处理并抽取通用题名页元数据；将标题和章节路径加入向量文本，升级 BGE-M3 系列模型并重建独立索引。
4. 将检索改成中文原问与英文查询扩展的多路 dense/BM25 召回，经 RRF 合并后保留 60 个候选统一重排；按内容、书目、作者关系和明确的多文档意图做结构化排序。
5. 修复 LangGraph 控制流：改写轮次累计并去重证据，最终回答逐字校验引用；对 DeepSeek 短任务关闭默认思考并增加空响应重试。
6. 定位并修复**多轮追问稳定拒答**：改写与检索都正确，问题出在证据判定用的是用户原话而非消解上下文后的独立问题，
   导致“检索成功”被“判定失败”抹掉；在状态里引入不被改写覆盖的 `standalone` 锚点，让判定与改写都锚在用户真实意图上。
7. 在切换前备份 PostgreSQL，以 `rag_chunks_v3` 完成蓝绿索引切换，验证 API、worker、Milvus、PostgreSQL、GPU embedding/reranker 和 checkpointer 全部健康。

## 高频面试追问

1. 为什么文档 Recall@5 很高，chunk Recall@5 却很低？
2. 为什么同时使用 dense、BM25、RRF 和 reranker？
3. 中文问题检索英文资料时，查询扩展为什么采用追加而不是替换？
4. 如何区分候选生成问题和重排问题？
5. 如何保证引用不是模型编造的？
6. 为什么改写重试需要累计证据？如何控制上下文膨胀？
7. 为什么不直接用余弦分或 RRF 分设置拒答阈值？
8. v3 索引如何做到可回滚切换？
9. 当前结果为什么不能直接证明“适用于所有学科”？
10. 如果文档规模增长到百万级 chunk，下一步怎样扩展？
11. **多轮追问为什么会拒答？怎么定位的？**
    - 现象：单轮指标正常，但只要问题基于上一轮回答，就稳定拒答。
    - 定位：把改写节点单独拉出来跑，改写是**对的**（`GBSVM 中粒度球分类器的时间复杂度大概是多少？`）。
      再单独跑检索，gold 块**也在候选里**，只是 top-1 重排分从 0.974 掉到 0.571。
      最后查 grader —— 它拿的是**用户原话**「那它大概要多久算完？」，
      而 `GRADE_PROMPT` 里不含对话历史（故意的），模型读不懂「它」是什么，只能判 insufficient。
    - 根因：**判据和检索不同源**。检索用消解后的独立问题，判定却用原话，
      于是"检索成功"被"判定失败"抹掉了。
    - 修法：在 state 里加 `standalone` 字段（消解上下文但**不被检索改写覆盖**），
      grader 与 rewrite 都锚在它上面。
    - 另一个独立缺陷：改写节点保留了口语「要多久算完」，丢掉了历史里已有的术语「时间复杂度」，
      导致重排分从 0.974 塌到 0.571 —— 口语说法在英文语料里根本不存在。
      在提示词里显式要求"用历史中的准确术语替换口语说法"后修复。
    - 一个反面教训：探针里我自编的「GBSVM 和 CKA-FSVM 哪个更快」，
      语料里两篇论文各说各的、没有可比数字，系统拒答**本来就是对的**；
      它之前"答出来了"是因为 grader 被骗（拿 A-only 的改写 query 去判，问什么答什么）。
      换用评测集里已证实可答的比较题（m02）才测出真实能力。
