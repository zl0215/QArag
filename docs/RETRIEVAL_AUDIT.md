# RAG 召回率审计与升级记录

日期：2026-09-14

## 结论

低召回的首要原因不是 Milvus 参数，而是 PDF 解析把双栏论文按页面纵坐标交错拼接。英文单词之间也因抽取容差过大而粘连，导致答案句本身成为不可检索的乱码段落。其次，摄取时没有把论文标题加入 embedding 文本；多篇 SVM 论文中的 “the proposed model” 因而难以区分。线上实际加载的模型还是 `bge-large-zh-v1.5` 与 `bge-reranker-base`，和 `.env` 声明的 BGE-M3 系列不一致，跨语言表示和重排结果也因此弱于预期。

原始评测进一步证明了这个定位：文档级 Recall@5 已有 0.950，但精确 chunk Recall@5 只有 0.500，说明系统通常能找到正确论文，却找不到包含答案的正确段落。

## 已实施改进

- PDF 解析改为版面感知：检测稳定栏间距，双栏按左栏再右栏读取；用更小的字符容差恢复英文空格；按二维边界过滤表格；移除重复页眉、页脚和页码；合并视觉换行并处理英文断词。
- 每个检索块的 embedding 输入现在包含论文标题和章节路径，摄取时按文档传入标题。
- 分块改为目标 256 token、上限 384 token、父块 1024 token，版本为 `v2-layout-multilingual`。
- embedding 升级到 `BAAI/bge-m3`，reranker 升级到 `BAAI/bge-reranker-v2-m3`；推理健康检查会返回实际模型名，防止配置与运行权重再次漂移。
- 保留中英文查询扩展、dense + BM25 混合召回和 cross-encoder 重排；多论文比较问题增加文档多样化，参考文献块在非书目问题中降权。
- PostgreSQL 回表增加 chunk 和 document 的软删除过滤，防止旧向量或旧分块被重新带回上下文。
- 新建 `rag_chunks_v2` 后离线重建全部 12 篇有效文档，共 956 个向量；验证通过后才切换正式读路径。旧集合 `rag_chunks` 保留用于回滚。

## 评测结果

评测集包含 30 道单跳、10 道多跳和 10 道不可回答问题。检索指标只统计 40 道可回答题。

| 指标 | 升级前 | 升级后 |
|---|---:|---:|
| chunk Recall@1 | 0.150 | 0.400 |
| chunk Recall@5 | 0.500 | 0.750 |
| chunk Recall@10 | 0.625 | 0.825 |
| chunk MRR | 0.306 | 0.552 |
| document Recall@5 | 0.950 | 1.000 |
| document MRR | 0.772 | 0.897 |
| 不可回答题拒答准确率 | 1.000 | 1.000 |
| 可回答题误拒率 | 0.175 | 0.150 |
| 引用逐字真实率 | 1.000 | 1.000（73/73） |

去掉 reranker 后，chunk Recall@5 从 0.750 降至 0.675，document Recall@5 从 1.000 降至 0.950。纯 BM25 的 chunk Recall@5 只有 0.575，因此正式配置继续使用混合召回与 BGE-M3 重排。

## 当前运行状态与回滚

正式 API 使用 `rag_chunks_v2`，就绪检查显示 956 个向量，PostgreSQL、embedding、reranker、LLM 和 checkpointer 均健康。AutoDL 的 8080 推理端口加载 `bge-m3` 与 `bge-reranker-v2-m3`。

回滚时可把 `.env` 的 `MILVUS_COLLECTION` 改回 `rag_chunks`，并恢复旧 embedding/reranker 服务。切换前 PostgreSQL 备份位于虚拟机 `/home/user/rag-backups/rag-pre-v2-20260914.dump`。旧集合和备份在确认新链路长期稳定前不应删除。

完整机器可读结果位于 `eval/results/retrieval.json`、`eval/results/chat.json`，自动生成报告位于 `eval/results/report.md`。

## v3 通用科研问答升级（2026-09-15）

这一轮按“中文提问、中文或英文资料、学科不限”设计，没有加入 SVM、粒度球或任何当前论文专用的查询词。论文只是现有回归语料，不能据此宣称已覆盖所有学科。

- PDF 题名页被解析为通用 `metadata` 块，保留标题、作者、机构、期刊/会议、年份和 DOI；规则同样适用于医学、理工、人文等含这些字段的文档。
- RRF 进入重排的候选从 30 增至 60，并为每条召回通道保留头部独有候选，减少跨语言或 BM25 单路强命中的证据在重排前被截断。
- 重排输入加入文档标题和章节路径；按候选语言分布选择中文、英文或双语查询，所有候选在同一次重排中比较，避免跨批次分数不可比。
- 普通内容问题降低参考文献与题名页元数据的排序；作者、共同作者和课题组比较问题优先题名页元数据；多文档问题优先覆盖不同文档。
- “多文档”只在问题明确提到多篇论文或多份文档时触发，避免把同一文档内的“两项分别比较”错误拆散；改写重试会累计、去重并限长保留证据，补充新线索时不再覆盖首轮结果。
- DeepSeek 问答链路关闭默认思考模式，防止短改写任务的 token 预算被思考过程耗尽而返回空正文；空响应仍会自动重试一次。
- 新建 `rag_chunks_v3` 并重建 12 篇有效文档，共 967 个向量。旧的 `rag_chunks_v2` 保留用于回滚。

同一组 40 道可回答题的最终回归结果：

| 指标 | 最初基线 | v2 | v3 通用版 |
|---|---:|---:|---:|
| chunk Recall@1 | 0.150 | 0.400 | **0.550** |
| chunk Recall@5 | 0.500 | 0.750 | **0.950** |
| chunk Recall@10 | 0.625 | 0.825 | **0.950** |
| chunk MRR | 0.306 | 0.552 | **0.729** |
| document Recall@1 | — | — | **0.925** |
| document Recall@5 | 0.950 | 1.000 | **1.000** |
| document MRR | 0.772 | 0.897 | **0.956** |

剩余两个 chunk 未命中样例都把正确文档排在第 1；其中一个已经返回语义等价的正确段落，但严格评测只认可预先标记的块。最终机器可读结果为 `eval/results/retrieval_v3_final.json`。广泛学科能力仍需用独立的多学科语料和问题集验证，后续新增该评测时不应修改当前回归集来追分。

50 题端到端问答回归中，不可回答题拒答准确率为 **100%（10/10）**，可回答题误拒率为 **5%（2/40）**，引用逐字真实率为 **100%（107/107）**。剩余两题分别含有“fold 是类别还是交叉验证折数”的歧义，以及缺少前文指代的“这几篇论文”；系统选择拒答比猜测更可靠。

正式读路径使用 `rag_chunks_v3`。切换前 PostgreSQL 备份位于虚拟机 `/home/user/rag-backups/rag-pre-v3-20260915.dump`；回滚只需把 `.env` 的 `MILVUS_COLLECTION` 改回 `rag_chunks_v2` 并重启 API 和 worker。
