# 通用多语言科研 RAG 助手：问题、方案、证据与优化路线

日期：2026-09-15  
交付阶段：**个人环境工程验证**  
当前版本：`v3-layout-metadata` / `rag_chunks_v3`

## 1. 问题背景

目标系统需要让用户用中文询问科研资料，同时允许知识库包含中文、英文及混合语言文档，学科不预设。系统应回答事实、方法、参数、对比、书目信息和跨文档问题，并在资料不足时拒答。

初始评测显示 document Recall@5 为 95.0%，chunk Recall@5 只有 50.0%。这意味着系统通常能找到相关文档，却不能稳定找到包含答案的具体段落。科研问答如果只有“相似论文”而没有精确证据，生成模型仍可能答错并挂上无关引用。

约束包括：

- 应用运行在本机，Milvus 与 PostgreSQL 位于虚拟机，embedding/reranker 位于 AutoDL GPU。
- 中文查询需要检索英文资料。
- PDF 可能含双栏、公式、表格、页眉页脚和损坏字符映射。
- 系统必须可回滚，不能直接覆盖当前可用索引。
- 当前材料主要用于回归验证，不能针对现有论文写死术语规则。

## 2. 方案决策

### 2.1 以分层评测驱动修改

同时测量 chunk 和 document 两层 Recall/MRR。document 命中说明选对资料，chunk 命中才说明找到了答案位置。问答层单独测量拒答准确率、误拒率和引用真实率，避免“只会拒答”的系统得到虚假的高分。

### 2.2 解析质量优先于向量参数

当答案句在解析阶段已被双栏交错、粘词或表格噪声破坏，调整 Milvus 索引参数无法恢复原文。因此先修解析和分块，再调召回与重排。

### 2.3 混合检索而非单路检索

- BGE-M3 dense 负责语义改写和跨语言相似性。
- BM25 负责型号、缩写、符号、专有名词和精确词面。
- RRF 用名次融合不同量纲的分数。
- Cross-encoder 对候选做精排。

### 2.4 PostgreSQL 为事实源，Milvus 为派生索引

正文、文档状态和任务状态以 PostgreSQL 为准；Milvus 只保存可重建的向量与检索字段。回表时同时过滤 chunk 和 document 的软删除状态，避免旧向量重新进入上下文。

### 2.5 蓝绿索引切换

建立新的 `rag_chunks_v3`，完成全部重建和评测后再修改正式配置。旧集合与数据库备份保留，失败时只需切回集合名并重启服务。

## 3. 当前架构

```text
PDF / Word / Markdown
        │
        ▼
版面感知解析 + 通用元数据抽取
        │
        ▼
结构化分块（256 target / 384 max / 1024 parent）
        │
        ├──────────────► PostgreSQL：正文、文档、任务、对话
        │
        └─ BGE-M3 ─────► Milvus：dense + BM25 sparse
                              │
中文问题 ─► 英文查询扩展 ─────┤
                              ▼
                    多路召回 → RRF → 60 候选
                              │
                              ▼
                bge-reranker-v2-m3 统一重排
                              │
                              ▼
          LangGraph：判定 → 改写补证据 → 生成 → 引用校验
```

## 4. 遇到的问题、根因与解决办法

| 问题与表现 | 根因 | 已实施方案 | 验证方式 | 还能怎样优化 |
|---|---|---|---|---|
| 双栏 PDF 内容前后交错 | 按整页纵坐标读取，左右栏被交替拼接 | 检测栏间距，按左栏再右栏排序；过滤页眉页脚、页码和表格区域 | 重建语料后证据短语映射 50/50 通过 | 引入 Docling/GROBID 对复杂版式做对照；按文档类型自动路由解析器 |
| 英文单词粘连、断词和 NUL 字节 | 字符容差过大、跨行连字符及 PDF 字体映射异常 | 调整字符容差、合并视觉换行、英文去断词，并在解析收口清理非法字符 | 文档重新入库成功，英文关键词可被 BM25 命中 | 对乱码率、字符覆盖率建立文档级质量门禁；异常页触发 OCR |
| 找到论文但找不到答案段落 | embedding 只有正文，缺少标题和章节语义；分块边界与答案不一致 | 标题与章节路径只加入 `embed_text`；采用结构感知小块与 parent 分组 | chunk R@5 50.0% → 95.0% | 加入相邻块上下文重排、late chunking 或按标题层级自适应块长 |
| 中文问英文资料时 BM25 几乎失效 | 词法通道没有中英文词面交集 | 保留中文原问并追加英文检索问句，四路并行召回 | 跨语言回归和消融验证 | 使用术语词典、缩写展开、语言识别后按目标语料生成多个查询变体 |
| 配置声明 BGE-M3，线上实际加载旧模型 | 配置与远程推理进程缺少一致性检查 | 推理 `/health` 返回实际模型名、设备和 GPU；就绪检查纳入依赖 | 当前返回 `bge-m3` 与 `bge-reranker-v2-m3` | 为索引记录模型指纹；查询模型指纹不一致时拒绝启动 |
| RRF 前 30 截断导致单通道强候选丢失 | 多通道共同命中会抬高 RRF，某一路独有的正确答案被过早裁掉 | 候选扩大到 60，并保留每个召回通道前 10 的独有结果 | 回归中原本被截断的证据进入 reranker | 按查询类型动态分配 dense/sparse 配额；记录每阶段的 gold 漏失 |
| 参考文献和题名页挤占正文 | 人名、期刊和术语密集，重排模型容易给高分 | 普通内容问题降低 reference/metadata；书目和作者问题按结构类型提升 | 普通问答正文结果增多，作者问题可直接命中题名页 | 将作者、机构、DOI 单独结构化为字段，使用字段检索而非全文启发式 |
| “分别/对比”被误判为多文档 | 仅凭措辞触发文档多样化，同一文档内第二个答案被推到第 11 名 | 只有明确出现多篇论文或多份文档时才做多文档覆盖 | 两个模型的数值块回到 top-2 | 增加轻量查询规划器，显式输出 single-doc/multi-doc/entity-relation 意图 |
| 改写一次后丢掉第一轮证据 | LangGraph 状态直接覆盖 `chunks`；改写只聚焦缺失子项 | 最多累计 `2 × top_k` 条，按 chunk_id 去重并重编引用序号 | 多跳比较和故障对比可以合并多轮证据 | 对复杂问题先分解子问题，每个子问题独立检索，再做证据覆盖检查 |
| DeepSeek 偶发返回空正文 | 当前模型默认开启思考，短改写任务的 token 预算可能被推理过程耗尽 | RAG 链路关闭默认思考；空响应自动重试一次 | 日志不再出现连续空正文，问答可稳定完成 | 区分任务配置：翻译/判定关闭思考，复杂综合回答按需开启并提高预算 |
| 有证据却误拒答 | grader 要求单个片段包含完整结论，不会合并多个编号 | 明确允许跨片段合并；列表题使用来源标签识别文档；比较题检查每个对象是否有证据 | 误拒率从初始 17.5% 降到 5.0% | 让 grader 输出“已覆盖/缺失子项”结构，而不只是二分类 |
| 旧向量和已删除文档可能回流 | Milvus 与 PostgreSQL 更新不同步 | 回表时过滤两层软删除；新版本写入独立集合 | `missing_in_postgres=0`，正式集合 967 向量 | 增加定期一致性扫描、孤儿向量清理和索引版本清单 |
| 重启后隧道或测试 Milvus 不可用 | SSH 隧道是本机进程；测试容器没有 restart policy | 重建本机隧道，恢复 GPU 推理，容器设为 `unless-stopped` | API `/readyz` 六项健康，worker 日志显示 v3 启动 | 将隧道与推理服务交给系统服务管理，并加入断线重连与告警 |

## 5. 个人动作与责任边界

### 可作为候选人项目动作表述

- 建立并运行分层评测，依据失败样例定位解析、召回、排序和 Agent 控制流问题。
- 设计并实现通用版面解析、元数据块、跨语言混合检索和结构化后处理。
- 完成 v3 索引重建、数据库备份、正式切换、回滚准备和端到端验证。
- 修复改写证据覆盖、错误多文档路由、LLM 空响应以及引用与拒答可靠性问题。

### 必须如实说明的边界

- 当前系统部署在个人本机、虚拟机和 AutoDL 账号组成的环境，属于工程验证；没有企业 SLA、真实用户规模或长期生产运行记录。
- 实现过程使用了 AI 编程辅助。简历可写你实际负责并能解释、复现的部分，不能把无法独立说明的代码细节包装为个人原创研究。
- 评测集与当前资料有关，能证明迭代的回归效果，尚不能证明所有学科上的同等准确率。
- “引用逐字真实”表示摘录确实来自声称的源块，不等同于自动证明整个回答的逻辑完全正确。

## 9. 后续优化路线

### P0：证明多学科通用性

- 建立互不重叠的开发集和多学科盲测集。
- 每个学科同时包含事实题、方法题、参数题、表格题、跨文档题、书目题和不可回答题。
- 报告 macro average，避免某一学科题量过多掩盖其他学科失败。

### P0：处理歧义和指代

- 对“这几篇”“它”“多少折”等依赖上下文或多义问题，先利用对话历史改写。
- 仍有多个合理解释时向用户提出一个澄清问题，避免凭当前语料猜答案。
- grader 改成输出 `covered_items`、`missing_items` 和 `ambiguities`。

### P1：提高复杂文档解析

- 增加 OCR 路由与扫描页检测。
- 对表格保留标题、表头和跨页续表关系；对公式保存 LaTeX/MathML 或公式图引用。
- 引入第二解析器做抽样对照，以字符质量、标题层级和阅读顺序评分自动择优。

### P1：查询规划和跨文档关系

- 将复杂问题拆成实体识别、子问题检索、证据覆盖和综合回答四步。
- 作者、机构、年份、DOI 等信息进入结构化字段；共同作者或研究团队查询使用关系索引。
- 对需要穷举的“有哪些”问题增加结果覆盖停止条件，避免只返回 top-k 中偶然出现的几篇。

### P1：上下文与重排

- 对命中小块加入相邻窗口后再重排，解决答案跨块边界的问题。
- 评估 late chunking、层级检索和 parent-child retrieval，不直接假设 overlap 一定有效。
- 在独立开发集上校准 reranker、RRF 和结构类型权重。

### P1：可观测性与可靠性

- 为每次请求保存查询变体、各通道名次、RRF、reranker、改写轮次和最终引用。
- 记录空响应率、误拒原因和每阶段延迟；设置隧道、GPU、数据库和 worker 告警。
- 使用系统服务管理 SSH 隧道与推理进程，增加断线重连和启动自检。

### P2：规模化

- 按租户、语种、文档类型和时间做标量过滤或分区。
- 引入 embedding、翻译和检索结果缓存；批量摄取时控制 GPU 队列和背压。
- 定期执行 PostgreSQL–Milvus 一致性校验、孤儿向量清理和索引版本审计。

## 11. 面试讲述建议

三分钟回答可以按以下顺序：

1. 先给结论：原系统不是“找不到论文”，而是“找不到答案段落”。
2. 给证据：document R@5 95%，chunk R@5 50%。
3. 讲两个关键根因：PDF 版面破坏文本；中文查询与英文语料让词法召回失效。
4. 讲方案：解析修复、标题/章节 embedding、多路召回、RRF、60 候选重排、Agent 证据累计。
5. 给最终数字：chunk R@5 95%，document R@5 100%，误拒率 5%，引用 107/107。
6. 主动说边界：当前是个人环境验证，多学科效果仍需盲测。
